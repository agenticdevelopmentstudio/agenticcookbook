

Emit production logs as structured JSON through the platform's logging framework, one category per component, using message templates rather than string interpolation so aggregation works (explicit-over-implicit). Carry a `trace_id` on every log line and span, propagated through the request context under one field name across services, and never write a secret or PII at any level (manage-complexity-through-boundaries). Create spans through the OpenTelemetry API, not a vendor SDK, so the backend stays swappable; model each unit of work as one span, and inject and extract W3C trace-context at the transport edge rather than in business logic (dependency-injection, separation-of-concerns).

Instrument every request-serving path with RED — rate and errors as counters, duration as a histogram so p95/p99 survive rather than a mean that hides the tail — and every finite resource with USE, saturation included (explicit-over-implicit). Keep label cardinality bounded: use route templates, never raw ids or URLs, as labels. Define an SLI as good-over-valid events measured closest to the user, set each SLO below 100%, derive the error budget as `1 − SLO`, and alert on burn rate over paired long and short windows rather than raw CPU (tight-feedback-loops).

Read every value that varies per deploy from the environment, coerce all required config into a typed object once at startup, and halt on a missing or malformed value rather than falling back to a silent default (fail-fast). Build one immutable image and promote it unchanged across environments; pin base images by digest, install from a locked manifest, run as a non-root user, and never bake a secret into a layer (immutability-by-default). Give each container one concern and declare CPU and memory requests with a memory limit; define readiness and liveness probes kept cheap and dependency-free so a probe never cascades a failure (support-automation). Reach for Kubernetes only when measured scale justifies its cost (yagni).
