
- `must-not-stack-uncommitted-changes`, `should-fix-broken-build-before-moving-on`: This prevents compound debugging sessions where multiple interacting changes all break at once.
- `should-plan-small-prs-before-coding`, `should-split-large-planned-units`, `should-decompose-large-agent-changes-before-review`: The decision to keep a change reviewable happens before code is written, not after. Large diffs degrade both human and AI reviewers, regardless of who reads them: once a change exceeds what fits in a reviewer's working context, review collapses into shallow pattern-matching rather than reasoning about correctness. Humans skim past detail and AI reviewers lose precision as context grows.
- `should-scrutinize-agent-code-more`: Plausible-looking code can hide subtle defects. That makes small, frequent diffs matter more here — more important for agent-authored work, not less, and not a luxury to be skipped under time pressure: a reviewer (human or AI) can hold a 50-line change fully in view, but not a 1,000-line one.
