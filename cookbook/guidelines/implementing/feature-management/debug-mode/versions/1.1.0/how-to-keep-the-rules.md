
- **Guard at compile time, everywhere the panel is touched.** Put the panel type, its entry point (the shake handler, the menu item, the route, the navigation item) and every call into it behind the same compile-time condition, so a release build contains none of them.
- **Swift.** Wrap the panel and its integration in `#if DEBUG … #endif`. Check that the Debug configuration's Active Compilation Conditions (`SWIFT_ACTIVE_COMPILATION_CONDITIONS`) contains `DEBUG` and the Release configuration's does not; a new Swift target sets it for Debug only. For shake access, override `motionEnded(_:with:)` in a responder that sits on the responder chain and open the panel when the motion is `.motionShake`.
- **Internal builds on Apple platforms.** A TestFlight build is built from the Release configuration, so `#if DEBUG` alone removes the panel from it. If testers need it there, give the internal build its own configuration and condition (for example `INTERNAL`), distribute it through TestFlight, and never submit a binary built with that condition to the App Store.
- **Android.** Put all of the panel's code, its shake detector included, in `src/debug/` (the debug source set) and its libraries in `debugImplementation`; where a library ships a no-op artifact (Chucker's `library-no-op`), add it under `releaseImplementation` so release code compiles without the real one. `src/main/` reaches the panel only through one entry point (for example `DebugPanel.install(app)`) that `src/debug/` implements and `src/release/` supplies as an empty no-op, so both variants compile and release holds no panel code. A `BuildConfig.DEBUG` check, if any, wraps only that call; on AGP 8 or later the module that reads it enables `buildFeatures { buildConfig = true }`. Keep the release build type's `isDebuggable` false, remove `Log` and `Debug` tracing calls, and turn WebView debugging off in release. For shake, register a `SensorManager` listener on the accelerometer and treat a burst of acceleration above a threshold as a shake.
- **C# and Windows.** Wrap the settings page, its registration and its navigation item in `#if DEBUG`. For a debug-only helper with a `void` return, `[Conditional("DEBUG")]` removes every call to it from Release builds without `#if` blocks at each call site; the method itself stays in the Release assembly, so wrap its body in `#if DEBUG` so that no panel code or reference remains there.
- **Web (bundled client).** Guard with `import.meta.env.DEV` under Vite or `process.env.NODE_ENV !== 'production'` under webpack; both are replaced with constants at build time, so the guarded branch is tree-shaken from production bundles. Lazy-load the panel module inside the guard so its code is not in the main chunk. The `/debug` route is a client route, registered in the bundled code inside that guard. On a Node.js server, `NODE_ENV` is `production` everywhere it is deployed, so it cannot guard server code: leave server-side debug endpoints out of the production deploy (for example, register them only from a development entry point that is never deployed) rather than switching them off at runtime.
- **Logs.** Route debug output through a logger whose debug and verbose levels are compiled out or disabled in release, redact headers such as `Authorization` and `Cookie` in network inspectors, and keep the inspector out of release builds, and never put a secret in the environment section of the panel.
- **SDK developer modes.** Turn a flag SDK's developer-tools option on only in debug builds (GrowthBook's `enableDevMode`); enable ASP.NET Core's Developer Exception Page only when the environment is `Development`.
- **Analytics.** Use the vendor's debug mode (Firebase DebugView) on development devices to validate events, and configure a developer-traffic data filter so those events stay out of reports and exports.
- **Production overrides.** If testers must override a flag or variant in production, sign the override (or require an authenticated session), keep the set of overridable flags small, and record the override in the threat model as added attack surface.
- **Check the release artifact.** Before release, search the release binary or bundle for the panel's type names, route and strings; finding any means a guard leaks.
