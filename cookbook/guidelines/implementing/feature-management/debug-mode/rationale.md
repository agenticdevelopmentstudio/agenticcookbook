
- **Debug features in release are a vulnerability.** Google's Android security guidance (mapped to OWASP MASVS-CODE) names hidden menus, debug-log toggles and options that alter application flow as test and debug features that must not be publicly accessible, and MITRE's CWE-489 classifies releasing active debug code as a weakness whose mitigation is removing it before deployment. A leaked debug feature can bypass paywalls and protections or leak system and user data, so its impact grows with what it can do.
- **Hiding is not removing.** Google says marking a debug component not exported is no protection, since a rooted device can still run it; Apple's App Review guideline 2.5.19 forbids hidden, dormant or undocumented features in the binary, and FLEX's maintainers warn that shipping it in Release gets an app rejected. Hence compile-time guards: Swift `#if`, C# `#if DEBUG`, Vite's and webpack's build-time constants, Android source sets and variant-scoped dependencies all remove the code rather than hide it. C#'s `[Conditional("DEBUG")]` removes only the calls to a method, not the method, so it is safe only when the method's body keeps its panel references inside `#if DEBUG`.
- **What the panel holds is what tools already offer.** GrowthBook DevTools overrides flags and variations and logs evaluation, Firebase DebugView streams raw events from development devices, and Pete Hodgson recommends exposing build metadata and the current flag state, which match the panel's flag overrides, variant picker, event log and environment info. Browser and React Native developer tools already cover the rest; React Native deprecated Flipper's native integration in 0.73.
- **Release hygiene beyond the panel.** Android's release checklist says to make the release build non-debuggable and to turn off logging and WebView debugging; OWASP MASWE-0005 and Chucker warn that debug logs and inspectors hold Authorization and Cookie headers and bodies. GrowthBook recommends turning its dev mode off in production, Microsoft says to enable the Developer Exception Page only in Development, and Vite warns that bundled values are public. Firebase includes debug-mode events in exports unless a developer-traffic filter removes them, and Pete Hodgson notes that production overrides let curious or malicious users flip flags.
- **Platform specifics.** Apple's HIG makes shake the iPhone undo gesture and Chrome binds Ctrl+Shift+D to bookmarking all tabs, so new gestures should avoid both kinds of collision; Android detects shake through its motion sensors. AGP 8 stopped generating `BuildConfig` by default, and the debug source set, not a `BuildConfig.DEBUG` check in `src/main/`, is what compiles the panel's code only into debug variants. Node.js calls any `NODE_ENV` other than `production` on a server an antipattern, so `NODE_ENV` is a sound guard only where a bundler replaces it, and server debug endpoints are kept out of the deploy, as CWE-489's mitigation says.
- **Questions left to the owner.** Whether the panel is Debug-only or also in internal, staging and TestFlight builds; whether every app must have a panel at all, which no source mandates; whether shake stays the iOS access gesture despite the HIG; and whether the TypeScript access method keeps its Ctrl+Shift+D shortcut, which Chrome binds.
