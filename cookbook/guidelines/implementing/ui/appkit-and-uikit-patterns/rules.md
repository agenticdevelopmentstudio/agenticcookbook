
- **should-use-nil-target-for-frontmost-commands**: A control whose target is `nil` sends its action up the chain until an object implements the method. Code SHOULD use that for commands that belong to whoever is frontmost (copy, delete, undo), and SHOULD set an explicit target for commands that belong to one object.
- **should-implement-actions-on-owning-object**: An action SHOULD be implemented on the object that owns the behavior, usually the view controller, not on a distant object reached through a stored reference.
- **should-override-nextresponder-sparingly**: To insert an object into the chain, code SHOULD override `nextResponder` and return it, and SHOULD do this sparingly; the default chain is what users and the system expect.
- **must-make-delegates-weak**: Delegate and data-source properties MUST be `weak` (or `unowned(unsafe)` on old APIs) so the owner does not keep its delegate alive and the delegate does not keep its owner alive.
- **should-use-narrow-delegate-protocols**: A delegate SHOULD be a protocol with narrow, named callbacks. Optional methods are acceptable in Objective-C protocols; in Swift, code SHOULD prefer a small required protocol plus default extension methods.
- **must-not-move-large-state-through-delegates**: A delegate callback is a notification that something happened or a request for a decision. A delegate callback MUST NOT move large state between objects; code SHOULD pass a value or use a closure for a single reply.
- **must-touch-ui-only-on-main-thread**: Code MUST touch views, windows, layers that back views, and view-controller state only on the main thread.
- **should-mark-ui-types-mainactor**: UI-facing types SHOULD be marked `@MainActor`, following Adopt Swift 6 strict concurrency incrementally ([adc.guideline.implementing.concurrency.swift6-strict-concurrency](cookbook:344b69da-c901-4650-b49d-c2df0234103b)).
- **must-run-slow-work-off-main-thread**: Slow work (disk, network, decoding, image processing) MUST run off the main thread and hop back only to apply the result.
- **must-not-block-main-thread**: Code MUST NOT block the main thread waiting for another queue or task.
- **must-do-one-time-setup-in-load-callbacks**: A view controller loads its view lazily. Accessing `view` the first time creates it, so one-time setup MUST go in the load callbacks and an initializer MUST NOT touch `view`.
- **must-pair-appearance-work-and-teardown**: Work that must happen every time the view appears MUST go in the appear and disappear callbacks, and setup MUST be paired with teardown (observers, timers, notification registrations) in the matching pair of callbacks.
- **should-keep-window-content-in-view-controllers**: On macOS (10.10 and later) `NSViewController` offers the same style of lifecycle methods, and its actions take part in the responder chain, so window content SHOULD live in view controllers and `NSWindowController` SHOULD be kept for window-level concerns.
- **must-follow-containment-sequence**: Containment is explicit: code MUST add a child view controller, add its view, then tell the child it moved to its parent, and reverse the steps to remove it.
- **must-implement-secure-restoration-callbacks**: State restoration is opt-in. On iOS, the app delegate MUST implement the secure save and restore callbacks (`application(_:shouldSaveSecureApplicationState:)` and `application(_:shouldRestoreSecureApplicationState:)`), MUST assign restoration identifiers to the view controllers to preserve, and MUST encode only the data needed to rebuild each one.
- **must-save-identifiers-not-model-objects**: Code MUST save identifiers and small values, not model objects, and MUST rebuild the screen from the model on restore.
- **should-version-saved-state**: Saved state SHOULD be versioned, and restoration MUST refuse an incompatible version and fall back to the normal launch UI.
