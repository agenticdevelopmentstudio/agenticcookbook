
- `must-make-source-single-authority`: every token value comes from the single token source
- `should-generate-outputs-with-transform-tool`: platform outputs are generated by a current release of a transform tool such as Style Dictionary, or the work says why not
- `must-not-hand-edit-generated-outputs`: generated outputs match a fresh regeneration from the source
- `should-regenerate-on-every-change-in-ci`: generation runs on every token change and in CI, or the work says why not
- `should-version-token-source`: the token source is versioned and consumers pin a release, or the work says why not
- `should-mark-outputs-generated`: every output is generated, committed or published, and carries a do-not-edit header, or the work says why not
- `must-derive-names-deterministically`: each token resolves to a symbol derived deterministically from its path on every platform
- `should-expose-semantic-tokens-not-primitives`: features reference semantic/alias tokens only, or the work says why not
- `should-run-generation-as-reproducible-step`: generation is a checked-in package script or task, or the work says why not
- `should-run-drift-check-in-ci`: a CI drift check regenerates and fails when outputs differ, or the work says why not
- `should-version-transform-config`: the transform configuration is in version control beside the token source, or the work says why not
- `should-adopt-managed-pipeline-only-on-measured-need`: the project uses a local build step, or the work names the measured need for more
- `must-not-maintain-parallel-token-files`: no platform has a hand-written token file
- `must-not-propagate-platform-edits-back`: every token change was made in the source and regenerated
- `should-not-hardcode-raw-values`: feature code uses tokens wherever one exists, or the work says why not
