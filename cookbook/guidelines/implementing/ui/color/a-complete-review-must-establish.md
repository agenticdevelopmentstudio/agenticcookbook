
- `should-use-semantic-color-tokens`: whether colors come from the platform's semantic colors rather than hard-coded hex values
- `should-limit-the-palette`: whether the palette is 1 primary/accent color, 1-2 neutral tones and semantic success/warning/error colors
- `must-not-rely-on-color-alone`: whether every state change, error and status pairs color with a secondary indicator
- `must-meet-contrast-minimums`: whether normal text meets 4.5:1, large text 3:1 and non-text UI components 3:1
- `must-work-in-light-and-dark`: whether every color works in both light and dark themes
- `should-test-light-and-dark`: whether the UI was tested in both themes
