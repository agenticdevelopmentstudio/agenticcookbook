
- **must-produce-sbom**: Every release build **MUST** produce, alongside the binary/package, **an SBOM** (Software Bill of Materials) listing every component and version.
- **should-use-one-sbom-format**: The SBOM SHOULD use **CycloneDX** or **SPDX** — both are widely tooled; pick one and stay consistent.
- **must-produce-signed-provenance**: Every release build **MUST** produce, alongside the binary/package, **signed build provenance** describing *what* built the artifact, *how*, and from *which* inputs (source commit, builder identity, parameters).
- **should-generate-sbom-from-lockfile**: The CI pipeline **SHOULD** generate the SBOM from the resolved dependency graph (lockfile), not from declared ranges, so it reflects what actually shipped.
- **should-generate-provenance-on-hosted-ci**: Provenance **SHOULD** be generated by the hosted CI platform itself, not by a step the build author fully controls — this is what raises trust from "self-asserted" to "platform-attested."
- **should-sign-artifacts-and-attestations**: Artifacts and attestations SHOULD be signed. Keyless signing tied to CI workload identity (e.g. Sigstore/cosign with OIDC) avoids long-lived private keys; managed KMS keys are an acceptable alternative.
- **should-pin-toolchain-by-digest**: The toolchain and base images SHOULD be pinned by digest so the build is reproducible enough to attest.
- **should-target-slsa-l2**: SHOULD target SLSA Build **L2** as a realistic baseline, and reach for L3 where the threat model justifies it.
- **must-verify-signature-before-deploy**: The deploy step **MUST** verify the artifact signature against the expected signer identity (CI workload, repo, ref).
- **should-verify-provenance-before-deploy**: The deploy step **SHOULD** verify provenance: the artifact was built from the expected source repo and commit, on the expected builder, with expected parameters. A signature without provenance only proves *who signed*, not *how it was built*.
- **must-block-promotion-on-failed-check**: A failed signature or provenance check **MUST** block promotion (fail-fast) — never warn-and-continue.
- **should-store-release-evidence**: SBOMs and attestations SHOULD be stored as immutable release evidence for incident response and audits.
- **should-commit-lockfiles**: SHOULD commit lockfiles, and install with the frozen/locked flag in CI so resolution is deterministic.
- **should-pin-dependencies-by-digest**: SHOULD pin dependencies (and CI actions) by version, ideally by digest/hash, not floating tags.
- **should-keep-scanning-for-vulnerable-components**: SHOULD keep scanning for known-vulnerable components — it answers a different question (*is this version exploitable?*) than provenance (*did this come from where I think?*).
- **must-not-ship-without-sbom-and-provenance**: MUST NOT ship a release build with no SBOM and no provenance.
- **must-not-pass-unverifiable-attestation**: MUST NOT treat an unsigned or unverifiable attestation as passing.
- **must-not-claim-hosted-trust-for-author-controlled-provenance**: MUST NOT generate provenance from a fully build-author-controlled step and claim hosted-build (L2) trust.
- **should-confirm-regulatory-applicability**: SHOULD confirm the regulatory drivers' current applicability for your jurisdiction and sector.
