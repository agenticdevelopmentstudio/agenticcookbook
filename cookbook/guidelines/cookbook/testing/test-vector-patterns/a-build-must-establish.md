
- `should-follow-arrange-act-assert`: each test vector gives its Arrange, Act and Assert, or says why it departs from the pattern
- `must-test-one-behavioral-concept`: every vector tests one behavioral concept
- `must-not-depend-on-other-vectors`: every vector is self-contained
- `should-target-public-api`: the vectors target the public API described in the requirements, or any that do not are explained
- `should-use-descriptive-specification-names`: every vector name reads as a specification, or the exception is explained
- `must-make-names-clear-enough-to-document`: every vector name is clear enough to serve, verbatim, as test documentation
