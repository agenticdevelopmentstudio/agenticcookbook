
- `must-have-yaml-frontmatter`: File starts with `---`, has closing `---` (S01)
- `should-have-name-field`: Frontmatter contains `name:` (S02)
- `must-use-kebab-case-name`: Regex: `^[a-z][a-z0-9-]{0,63}$` (S03)
- `must-have-description-field`: Frontmatter contains `description:` (S04)
- `should-use-natural-trigger-keywords`: Description includes phrases users would say; not too vague ("does stuff") or too narrow ("only for X on Tuesdays") (S05)
- `should-keep-skill-md-under-500-lines`: `wc -l SKILL.md` (S06)
- `should-put-supporting-files-in-subdirectories`: Loose files (non-SKILL.md) at skill root → should be in references/, scripts/, examples/ (S07)
- `should-reference-supporting-files`: If references/ exists, SKILL.md mentions those files or uses `${CLAUDE_SKILL_DIR}` to load them (S08)
- `should-match-directory-to-name`: Compare directory basename to frontmatter `name` (S09)
- `should-have-argument-hint-when-using-arguments`: SKILL.md uses `$ARGUMENTS` or `$1`, `$2` but frontmatter lacks `argument-hint:` (S10)
- `should-be-in-skills-directory`: Skill is in `.claude/skills/` or `~/.claude/skills/` (S11)
- `should-use-only-recognized-frontmatter-fields`: Check against known fields: name, description, argument-hint, disable-model-invocation, user-invocable, allowed-tools, model, effort, context, agent, hooks, paths, shell (S12)
- `must-name-main-file-skill-md`: Filename is exactly `SKILL.md`, not `skill.md` or `Skill.md` — Claude Code looks for this exact name (S13)
- `should-use-lowercase-descriptive-supporting-names`: Files in references/, scripts/, examples/ match `^[a-z][a-z0-9-]*(\.[a-z]+)+$`; names describe content (not `doc1.md`) (S14)
- `should-have-single-responsibility`: Skill has one clear purpose; not a grab-bag of unrelated instructions (C01)
- `should-give-task-skills-step-by-step-instructions`: If the skill performs actions (not just reference), it should have numbered steps or a clear workflow (C02)
- `should-keep-reference-and-task-content-apart`: Reference skills (background knowledge) should not have imperative "do X" steps; task skills should not be pure documentation (C03)
- `should-cover-error-handling`: Instructions address what to do when things go wrong (tool failures, missing files, bad input) (C04)
- `should-use-arguments-when-accepting-input`: Description implies the skill takes input but body never references `$ARGUMENTS` (C05)
- `must-use-claude-skill-dir-for-file-references`: Skill references its own supporting files using `${CLAUDE_SKILL_DIR}`, not hardcoded paths (C06)
- `should-give-actionable-specific-instructions`: Steps tell Claude what to do concretely, not vague directives like "handle errors appropriately" (C07)
- `must-not-conflict-with-itself`: Body does not contradict itself (e.g., "always do X" then later "never do X") (C08)
- `should-use-well-structured-markdown`: Uses headings, lists, code blocks; not a wall of unstructured text (C09)
- `should-not-duplicate-supporting-files`: SKILL.md and reference files don't duplicate large blocks of the same content (C10)
- `should-provide-verification-method`: Skill includes how to validate it worked (run tests, check output, verify file exists) (B01)
- `should-not-replicate-native-capabilities`: Skill doesn't teach Claude things it already knows (basic git, standard coding, etc.) (B02)
- `should-disable-model-invocation-for-side-effects`: Skills that deploy, commit, send messages, or modify external state should set `disable-model-invocation: true` (B03)
- `may-use-context-fork-for-isolated-tasks`: Task skills that do heavy reading/fetching and return a result benefit from fork isolation (B04)
- `should-include-usage-examples`: Skill body or references include at least one example invocation or expected output (B05)
- `must-not-be-kitchen-sink`: Skill doesn't try to do everything — stays focused on its stated purpose (B06)
- `should-not-explore-unbounded`: Task skills scope their investigation; don't read unbounded numbers of files (B07)
- `should-not-be-claude-md-dump`: Skill content is skill-appropriate, not a copy-paste of project rules that belong in CLAUDE.md (B08)
- `may-use-allowed-tools-for-restriction`: If the skill should only use certain tools, `allowed-tools` is set (B09)
- `should-match-model-override-to-complexity`: If `model:` is set, it matches the skill's complexity (don't use opus for trivial tasks) (B10)
- `should-keep-dynamic-context-injection-safe`: If `` !`command` `` syntax is used, the command is safe, fast, and deterministic (B11)
- `should-keep-description-under-200-characters`: Description is under ~200 characters to avoid consuming excessive context (B12)
