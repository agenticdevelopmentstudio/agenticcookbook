
- `must-have-yaml-frontmatter`: File starts with `---`, has closing `---` (S01)
- `should-have-name-field`: Frontmatter contains `name:` (S02)
- `must-use-kebab-case-name`: Regex: `^[a-z][a-z0-9-]{0,63}$` (S03)
- `must-have-description-field`: Frontmatter contains `description:` (S04)
- `should-use-natural-trigger-keywords`: Description includes phrases users would say; not too vague or too narrow (S05)
- `should-be-in-agents-directory`: Agent is in `.claude/agents/` or `~/.claude/agents/` (S11)
- `should-use-only-recognized-frontmatter-fields`: Check against known fields: name, description, tools, disallowedTools, model, permissionMode, maxTurns, skills, mcpServers, hooks, memory, background, effort, isolation (S12)
- `should-use-lowercase-kebab-case-filename`: Filename matches `^[a-z][a-z0-9-]*\.md$`; UPPERCASE stems are reserved for identity files like `SKILL.md` and `CLAUDE.md` (S13)
- `should-have-single-responsibility`: Agent has one clear purpose; not a grab-bag of unrelated tasks (C01)
- `should-cover-error-handling`: System prompt addresses what to do when things go wrong (tool failures, missing files, bad input) (C04)
- `should-give-actionable-specific-instructions`: System prompt tells the agent what to do concretely (C07)
- `must-not-conflict-with-itself`: Body does not contradict itself (C08)
- `should-use-well-structured-markdown`: Uses headings, lists, code blocks; not a wall of unstructured text (C09)
- `should-provide-verification-method`: Agent includes how to validate it completed successfully (B01)
- `should-not-replicate-native-capabilities`: Agent doesn't teach Claude things it already knows (B02)
- `should-include-usage-examples`: Body or description includes expected usage context (B05)
- `must-not-be-kitchen-sink`: Agent doesn't try to do everything — stays focused on its stated purpose (B06)
- `should-not-explore-unbounded`: Agent scopes its investigation; doesn't read unbounded numbers of files (B07)
- `should-not-be-claude-md-dump`: Agent content is agent-appropriate, not a copy-paste of project rules that belong in CLAUDE.md (B08)
- `should-match-model-override-to-complexity`: If `model:` is set, it matches the agent's complexity (B10)
- `should-keep-description-under-200-characters`: Description is under ~200 characters to avoid consuming excessive context (B12)
- `must-have-name-and-description`: Agent .md file has both fields (A01)
- `should-restrict-tool-access`: `tools` or `disallowedTools` limits access for specialized agents (A02)
- `may-specify-model`: Agent benefits from a specific model for its task (A03)
- `should-have-clear-focused-system-prompt`: Markdown body gives the agent a clear role and scope (A04)
- `should-set-permission-mode-appropriately`: `plan` for read-only agents, `bypassPermissions` for fully automated (A05)
- `should-set-max-turns-for-bounded-tasks`: Simple agents that should finish quickly have a turn limit (A06)
- `may-preload-skills`: Agent that needs domain knowledge has relevant skills preloaded (A07)
- `may-scope-memory`: If agent accumulates knowledge, memory is scoped correctly (A08)
