
- `should-build-the-steel-thread-first`: whether a thinnest end-to-end slice through every integration boundary and the deployment path was proven before breadth was built
- `should-keep-the-thread-thin-but-complete`: whether the thread is one real path through every layer and boundary rather than a finished feature
- `should-build-the-shell-only-for-the-committed-path`: whether the shell was built only for the committed path that is expensive to wire up later
- `should-not-pre-build-unneeded-features`: whether any feature, option, or abstraction was pre-built before it was needed
- `should-front-load-risky-integrations`: whether the thread pierces the boundaries most likely to surprise (auth, third-party APIs, the deploy pipeline)
- `should-validate-shape-before-breadth`: whether the agent validated the end-to-end shape before spending effort on breadth
