
- `should-answer-to-one-actor`: a module that two actors can each independently demand changes to
- `should-split-modules-two-stakeholders-drive`: a module that two stakeholders can drive changes to independently, left unsplit
- `should-keep-code-that-changes-together-together`: code that changes together split apart, or code that changes for different reasons merged because it looks similar
- `should-treat-unexpected-merge-conflicts-as-a-signal`: a module where unrelated features keep colliding in merge conflicts
- `should-prefer-narrow-units`: a long function or wide class that multiple actors share
