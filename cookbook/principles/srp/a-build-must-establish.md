
- `should-answer-to-one-actor`: each module is answerable to one and only one actor, or the work says why not
- `should-split-modules-two-stakeholders-drive`: each anticipated change request is traced to a stakeholder and no module is driven independently by two, or the work says why not
- `should-keep-code-that-changes-together-together`: code that changes together is together and code that changes for different reasons is separate, even where it looks similar, or the work says why not
- `should-treat-unexpected-merge-conflicts-as-a-signal`: no module draws unexpected merge conflicts between unrelated features, or the work says why
- `should-prefer-narrow-units`: units are narrow, each answerable to one actor, with no long function or wide class shared by several, or the work says why not
