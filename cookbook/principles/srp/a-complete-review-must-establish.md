
- `should-answer-to-one-actor`: whether each module is answerable to one and only one actor
- `should-split-modules-two-stakeholders-drive`: whether each anticipated change request was traced to a stakeholder, and any module two stakeholders can drive independently was split
- `should-keep-code-that-changes-together-together`: whether code that changes together is kept together and code that changes for different reasons is separated
- `should-treat-unexpected-merge-conflicts-as-a-signal`: whether unexpected merge conflicts between unrelated features point to a module serving more than one actor
- `should-prefer-narrow-units`: whether long functions or wide classes are shared by multiple actors where narrow units would each answer to one
