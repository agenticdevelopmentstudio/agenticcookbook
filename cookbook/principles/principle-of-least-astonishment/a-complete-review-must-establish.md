
- `should-match-caller-expectations`: whether APIs, UI, and system behavior match what users and callers expect
- `must-deliver-the-behavior-a-name-suggests`: whether every name delivers the behavior it suggests
- `should-make-side-effects-obvious-from-signature`: whether each side effect is obvious from the API signature
- `should-name-for-predictability`: whether a reader can predict what each function and type does from its name, without reading the implementation
- `must-make-mutation-visible`: whether every method that mutates state shows it in its name or signature
- `should-follow-platform-naming-conventions`: whether names follow the platform's naming conventions
- `should-ask-would-a-new-team-member-be-surprised`: whether a new team member would be surprised by any behavior in the change
