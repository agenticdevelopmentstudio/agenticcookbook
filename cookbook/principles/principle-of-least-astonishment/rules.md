
- **should-match-caller-expectations**: APIs, UI, and system behavior SHOULD match what users and callers expect.
- **must-deliver-the-behavior-a-name-suggests**: If a name suggests one behavior, it MUST deliver that behavior.
- **should-make-side-effects-obvious-from-signature**: Side effects SHOULD be obvious from the API signature.
- **should-name-for-predictability**: SHOULD name functions and types so a reader can predict what they do without reading the implementation.
- **must-make-mutation-visible**: If a method mutates state, MUST make that visible in the name or signature — never hide side effects.
- **should-follow-platform-naming-conventions**: SHOULD follow platform naming conventions even when you prefer a different style.
- **should-ask-would-a-new-team-member-be-surprised**: When reviewing code, SHOULD ask: "Would a new team member be surprised by this behavior?"
