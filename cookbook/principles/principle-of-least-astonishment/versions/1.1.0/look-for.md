
- `should-match-caller-expectations`: an API, UI, or behavior that does something users or callers would not expect
- `must-deliver-the-behavior-a-name-suggests`: a name that suggests one behavior while the code does another
- `should-make-side-effects-obvious-from-signature`: a side effect that the API signature gives no hint of
- `should-name-for-predictability`: a function or type whose name does not let a reader predict what it does
- `must-make-mutation-visible`: a method that mutates state with nothing in its name or signature showing it
- `should-follow-platform-naming-conventions`: names that break the platform's naming conventions in favour of a personal style
- `should-ask-would-a-new-team-member-be-surprised`: behavior a new team member would be surprised by
